## Act 2: Journey (70-80% of time)

**Purpose**: Alternate between problem and solution, building evidence

### Cycle 1: Content vs Formatting

**What Is** (Problem):
Every presentation starts the same way: copy an old deck, delete slides you don't need, hope the formatting doesn't break. You spend 30 minutes adjusting margins before writing a single word.

**What Could Be** (Solution):
Define your content in JSON. Let the library handle formatting. Your slides become data - portable, versionable, reviewable in pull requests.

**Evidence**: demo
- Show a JSON config file with slide content
- Run `node cli.js config.json output.pptx`
- Open the generated presentation
- Point out: "Notice I never touched PowerPoint"

**Teaching Moment**:
"The key insight here is separation of concerns. Content is data. Formatting is code. When you separate them, you can change either independently."

**Transition**: "But generating one presentation isn't that impressive. What about consistency across dozens of decks?"

---

### Cycle 2: Brand Consistency at Scale

**What Is** (Problem):
Your team's presentations look like they came from different planets. Marketing uses one shade of blue, engineering uses another, sales picked their own font. The CEO asks "why don't our decks look professional?"

**What Could Be** (Solution):
Define your brand once in a theme file. Every presentation - whether generated by marketing, engineering, or sales - uses the exact same colors, fonts, and spacing. Automatically.

**Evidence**: demo
- Show the theme file (src/themes/cowork.js)
- Generate same content with two different themes
- Side-by-side comparison: "Same content, completely different visual identity"

**Teaching Moment**:
"This is how enterprise software works. You don't let every developer pick their own color scheme. You define it once, enforce it everywhere."

**Transition**: "Great, we have consistent branding. But how do we know the content itself is correct?"

---

### Cycle 3: Quality Assurance for Presentations

**What Is** (Problem):
You generate 100 presentations for a customer event. One has a typo in the footer. One has last quarter's data. One has the wrong product name. How do you find them? Open each file and manually check?

**What Could Be** (Solution):
Automated QA. The qa.js tool extracts all text from generated PPTX files and validates against expected content. Run it in CI/CD. Catch errors before they ship.

**Evidence**: demo
- Run: `node qa.js output.pptx config.json`
- Show the validation output with checkmarks
- Show what a failure looks like
- "Exit code 0 means pass. Exit code 1 means fail. This can gate your deployment."

**Teaching Moment**:
"This is CI/CD for presentations. Every pull request can validate that generated content matches expectations. You'd never ship code without tests - why ship presentations without validation?"

**Transition**: "Let's put the full workflow together."

---

### Cycle 4: The Complete Pipeline

**What Is** (Problem):
You have content in a database, CMS, or API. Getting it into PowerPoint means copy-paste, manual formatting, and hoping nothing breaks when the source data changes.

**What Could Be** (Solution):
A three-step pipeline: source data transforms to JSON config, CLI generates PPTX, QA validates output. Scriptable. Automatable. Reproducible.

**Evidence**: demo
- Show end-to-end: JSON -> CLI -> PPTX -> QA
- "Run this command today, next week, next year - you get the same result"
- Show Docker usage for environments without Node.js

**Teaching Moment**:
"The magic isn't the tool - it's making presentations reproducible. Same input, same output, every time. No more 'works on my machine' for slides."

**Transition**: "Let me show you how to get started yourself."

## Act 3: Resolution (10-15% of time)

**Purpose**: Call to action and vision of the new reality

### Key Takeaways

1. **Separate content from presentation**: JSON for what you say, code for how it looks. This enables version control, code review, and automation.

2. **Theme once, use everywhere**: Define your brand in one place. Every presentation - regardless of who generates it - looks professional and consistent.

3. **Validate automatically**: QA tools catch errors before your audience does. Treat presentations like code: test before you ship.

### Call to Action

**Primary Action**: Clone the repo and run the example
```bash
git clone https://github.com/jabelk/pptx-generator.git
cd pptx-generator && npm install
node examples/basic.js
```

**Secondary Action**: Take one real presentation and convert it to JSON

**Phrasing**:
"Before your next presentation, try this: take your content, put it in JSON, and let the code handle formatting. I guarantee you'll save time. And you'll never go back to manually aligning bullets."

### New Bliss (Vision)

"Imagine a world where you spend your presentation prep time on what to say, not how slides look. Where every deck from your organization is perfectly on-brand, automatically. Where a last-minute logo change is a one-line config update, not a two-hour ordeal. Where you can generate 500 personalized presentations while you get coffee."

"That's the world PptxGenerator enables. And it's ready for you today."
